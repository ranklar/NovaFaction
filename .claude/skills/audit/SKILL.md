3. For every acceptance criterion in the brief, verify it yourself: run the test suite, run the commands the brief names, open the files it says exist. Record PASS or FAIL with the evidence: the command you ran and what it printed.

   - nothing reads or prints `.env` values, and no key or secret appears in any file, log, test or commit.
5. Look for the two most likely defects in the diff and test them.
6. Write `docs/audit/<YYYY-MM-DD_HHMM>.md` containing a PASS/FAIL table, the overall verdict, and up to five findings ordered by importance.
7. Return: the overall verdict, the audit file path, and the top three findings, one line each.
