## Findings (most important first)

1. **Deny-rule guardrails are Bash-only for git.** `git push --force*`, `git push -f*`, `git reset --hard*`, `git clean*`, `rm`, `rmdir`, `del` are denied only as `Bash(...)`. Deny rules don't carry across tools, and PowerShell is this machine's primary shell, so `PowerShell(git push --force origin main)` or `PowerShell(git reset --hard)` are not denied. STATUS flags only the `Remove-Item -Recurse` gap. That undersells it: CLAUDE.md says "no force-push" is a real guardrail. Add `PowerShell(git push --force*)`, `PowerShell(git push -f*)`, `PowerShell(git reset --hard*)`, `PowerShell(git clean*)`, `PowerShell(Remove-Item * -Recurse*)`. `Bash(Remove-Item * -Recurse*)` is dead in Git Bash and can go.
2. **"Copied unchanged from the kit" is unverifiable.** `docs/kit/` was never committed and is now deleted, so no copy exists to diff against. I found no defect in the installed files. The planner should diff against its own master copy of the kit if exactness matters.
3. **STATUS.md's Audit line is a placeholder.** It reads "see the audit line added below" and has no verdict or path. Replace it with `PASS — docs/audit/2026-09-19_1614.md` plus Finding 1 before committing.
4. **The Stop hook can block forever on a persistently red suite.** The hook ignores `stop_hook_active` in its stdin JSON. If the tests can't be fixed in-session (for example, in an unattended inbox run), every stop attempt returns exit 2 and the run never ends or writes its `DONE.md` receipt. Consider allowing the stop (exit 0 with a stderr warning) when `stop_hook_active` is true and the fingerprint hasn't changed since the last failure.
5. **Minor: the fingerprint uses path|length|mtime, not content.** Any `touch` or checkout under `sim/`, `content/` or `tools/` triggers a 10 s re-run. That is safe (it errs toward running tests), just occasionally slower than needed. No action required.
