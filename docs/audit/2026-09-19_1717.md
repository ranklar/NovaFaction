## The fix actually works (the point of the brief)

Not just "the sync was quiet once" — the build is reproducible:

- **Forced recompile at a different commit.** The committed DLL was built while HEAD was `2180496`. With HEAD now `c336f97`, `dotnet build … -c Release --no-incremental` produced SHA256 `40A1F2B8…84DDF8` — byte-identical to the committed DLL. So the commit id no longer reaches the output.
- **Clean rebuild.** `dotnet clean -c Release` followed by `dotnet build -c Release` also produced `40A1F2B8…84DDF8`. The result is not an artifact of an incremental build or a stale `obj/`.
- **No sha in the binaries.** `FileVersionInfo` on the committed DLL: `ProductVersion: 1.0.0` (previously `1.0.0+<sha>`), `FileVersion: 1.0.0.0`. The generated `obj/Release/netstandard2.1/NovaFaction.Sim.AssemblyInfo.cs` has `AssemblyInformationalVersionAttribute("1.0.0")` with no `SourceRevisionId`. A byte scan of the DLL and the Release PDB for the current short sha found no match.
- **Nothing else broke.** `tools\NovaFaction.Harness` builds clean in Release (0 warnings, 0 errors) and 889 sim tests pass.
